# AMM-Docker (Automated Monolith Migration to Docker)

Инструментальное средство для автоматизированной контейнеризации монолитных Python-приложений. Проект разрабатывается в рамках выпускной квалификационной работы (ВКР).

## Описание проекта

Цель системы — упростить процесс миграции устаревших монолитных систем на микросервисную архитектуру путём автоматической генерации Docker-артефактов (`Dockerfile`, `docker-compose.yaml`, `nginx.conf`) на основе статического анализа структуры исходного кода.

## Технологический стек

| Компонент | Технология |
|---|---|
| Core | Python 3.10+, Flask |
| Анализ | Static structure scanning (`scanner.py`) |
| Шаблонизация | Jinja2 |
| Контейнеризация | Docker, Docker Compose |
| API Gateway | Nginx |
| GUI | CustomTkinter |

## Архитектура после миграции

После запуска миграции монолит преобразуется в систему независимых контейнеров:

- **Изоляция:** каждый модуль (Blueprint) получает собственный контейнер с отдельным `requirements.txt` и `Dockerfile`.
- **Сетевое взаимодействие:** все сервисы объединены в сеть `app-network`.
- **Маршрутизация:** входящие запросы распределяются через Nginx (порт 8888) по URL-префиксам сервисов.
- **База данных:** PostgreSQL с персистентным Docker Volume (`postgres_data`).
- **Заглушки (Stubs):** автоматически генерируемые Mock-объекты для импортов из других сервисов.
- **API Bridge:** внутренний Blueprint `/internal` для межсервисного взаимодействия.

## Ключевые возможности

### Автодекомпозиция Blueprint-ов

Если в папке монолита обнаружено **несколько `Blueprint`-определений**, сканер автоматически создаёт отдельный микросервис для каждого из них, определяя имя и `url_prefix` из аргументов конструктора Blueprint. Папки с одним Blueprint обрабатываются как единый сервис.

### Умный entrypoint

Каждый сервис запускается через сгенерированный `run.py`, который:
1. Пытается найти и использовать оригинальный `create_app()` или `app`-объект монолита.
2. При неудаче — создаёт Flask-приложение самостоятельно и автоматически инициализирует расширения из `extensions.py`.
3. Регистрирует Blueprint с правильным `url_prefix`.
4. Создаёт таблицы БД через `db.create_all()`.
5. Отдаёт HTML-страницу со списком всех маршрутов сервиса по корневому URL.

### Копирование общих ресурсов

Генератор автоматически копирует в каждый сервис:
- `db.py` из корня монолита (или генерирует минимальный, если отсутствует).
- Корневые `.py`-файлы: `models.py`, `config.py`, `extensions.py` и т.д.
- Папки `templates/` и `static/` из корня монолита.

### Безопасность

- `.env` генерируется со случайным `POSTGRES_PASSWORD` и `SECRET_KEY`.
- Рядом создаётся `.env.example` с заглушками для документирования.

## Инструкция по запуску

### 1. Подготовка

Поместите исходный монолит в рабочую директорию. Убедитесь, что модули разделены по папкам.

### 2. Сканирование и генерация (GUI)

```bash
python main_gui.py
```

Укажите путь к монолиту и нажмите **«Генерировать»**. Результат появится в папке `docker_out/`.

### 3. Развёртывание

```bash
cd docker_out
docker compose up --build
```

### 4. Проверка

- Nginx Gateway: `http://localhost:8888`
- Health-check каждого сервиса: `http://localhost:8888/<service>/health`
- Отдельные порты сервисов: начиная с `5001`, `5002`, ...

### 5. Остановка

Через GUI кнопка **«Stop Containers»** выполняет `docker compose down` (volume с данными БД сохраняется).

### 6. Полное удаление окружения

Кнопка **«Удалить docker_out + БД»** (появляется после генерации):
- Останавливает контейнеры и удаляет volume `postgres_data`.
- Удаляет папку `docker_out` со всеми сгенерированными файлами.
- Оригинальный код монолита не затрагивается.

## Структура проекта

```
AMM-Docker/
├── main_gui.py              # GUI-приложение (CustomTkinter)
├── src/
│   ├── scanner.py           # Статический анализ монолита
│   └── generator.py         # Генератор Docker-артефактов
├── templates/
│   ├── entrypoint.jinja2    # Шаблон run.py для каждого сервиса
│   ├── docker-compose.jinja2
│   ├── nginx.conf.jinja2
│   └── api_bridge.jinja2    # Шаблон внутреннего API
└── docker_out/              # Генерируется автоматически
    ├── .env
    ├── .env.example
    ├── docker-compose.yaml
    ├── nginx.conf
    └── <service_name>/
        ├── Dockerfile
        ├── run.py
        ├── requirements.txt
        └── <source_code>/
```
