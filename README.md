# AMM-Docker (Automated Monolith Migration to Docker)

Инструментальное средство для автоматизированной контейнеризации монолитных Python-приложений. Проект разрабатывается в рамках выпускной квалификационной работы (ВКР).

## 📌 Описание проекта
Цель системы — упростить процесс миграции устаревших монолитных систем на микросервисную архитектуру путем автоматической генерации Docker-артефактов (Dockerfile, docker-compose.yaml) на основе анализа структуры исходного кода.

## Технологический стек
* **Core:** Python 3.10+, Flask
* **Analysis:** Static structure scanning (scanner.py)
* **Templating:** Jinja2 (для генерации Docker-файлов и entrypoints)
* **Containerization:** Docker, Docker Compose
* **GUI:** Custom Migration Assistant (на базе Tkinter/PyQt)

## Текущая архитектура после миграции
После запуска миграции, проект преобразуется из единого репозитория в систему независимых сервисов:
* **Изоляция:** Каждый модуль (например, `users`, `orders`, `products`) получает собственный контейнер.
* [cite_start]**Сетевое взаимодействие:** Сервисы объединены в общую сеть `app-network`.
* [cite_start]**Маршрутизация:** Доступ к сервисам осуществляется по именам контейнеров через порт `5000`.
* **Автоматические заглушки (Stubs):** Генератор создает Mock-объекты для импортов, чтобы предотвратить `ModuleNotFoundError` при обращении к еще не вынесенным частям кода.

## Инструкция по запуску

### 1. Подготовка
Поместите ваш исходный монолит в рабочую директорию. Убедитесь, что модули разделены по папкам.

### 2. Генерация (Migration Assistant)
Запустите графический интерфейс и укажите путь к исходному коду. Нажмите **"Запустить миграцию"**. Результат будет сформирован в папке `docker_out`.

### 3. Развертывание
Перейдите в сгенерированную папку и запустите сборку:
    ```bash
    cd docker_out
    docker compose up --build
### 4. Проверка статуса
    После успешного запуска:

    Сервис Orders будет доступен на внутреннем IP (например, 172.18.0.4).

    Сервис Products будет доступен на внутреннем IP (например, 172.18.0.3).

    Сервис Users будет доступен на внутреннем IP (например, 172.18.0.2).

    Эндпоинт /health каждого сервиса подтвердит его работоспособность.

## Особенности реализации

    Динамический entrypoint: Каждый сервис запускается через кастомный entrypoint.py, который автоматически регистрирует Blueprints и настраивает подключение к БД.

    API Bridge: Автоматическая генерация серверной части для межи сервисного взаимодействия.

    Добавлена поддержка Nginx API Gateway 

    HTTP Client: Готовый клиент для выполнения запросов между контейнерами.
